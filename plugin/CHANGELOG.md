# Changelog

## Unreleased

- New: panes return to their last live folder after herdr restarts, as a workaround for herdr issue #5199 (https://github.com/herdrdev/herdr/issues/5199), where herdr 0.9.5 restores each pane in its spawn folder. An event hook (`cwd-record.sh`, `cwd-record.ps1`) records the folders without polling: on each pane, tab or space focus, pane create, move, close or exit, and tab or space close, it reads `herdr pane list` once and updates `cwd-<session>.txt` in the plugin state directory (`<pane>`, live folder, spawn folder and shell pid, tab-separated, plus on Windows herdr's shell pid for a Git Bash pane; a lock file `cwd-<session>.txt.lock` serializes overlapping runs, and a run that finds it taken leaves a request for the holder to merge once more, so a burst of hooks collapses into a few merges instead of failing). For Windows Git Bash, whose herdr `cwd` stays at the spawn folder, it reads the live folder from the MSYS shell process (`/proc/<pid>/cwd`, through Git's own `ps.exe` and `bash.exe`), all panes in one Git Bash run, so no shell configuration is needed; one hook run takes about 1 s with 2 or 14 Git Bash panes (measured 2026-10-24). Nothing runs in the background. A new `startup` hook (`cwd-return.sh`, `cwd-return.ps1`) records the restored panes, waits until each restored shell is ready (a Windows Git Bash pane as soon as its MSYS shell process exists, any other shell at its first prompt) and runs `herdr pane run <pane> "cd '<folder>'"` only into idle shells (no agent, no running program, recorded folder exists and differs, recorded and restored spawn folders known and equal), then records again once the returned panes are in their folders. A pane whose id herdr reused for a different spawn folder is skipped as `mismatch`. herdr has no hook for a folder change, a title change or a stop, so a `cd` followed by a server stop with no hooked event in between is recorded as of the last hook, under any prompt: that pane comes back in its earlier recorded folder or stays where herdr put it, never in another pane's. It logs one line per startup, `cwd-return: N panes returned, M skipped (<reason>=<count>, ...)`. `NOTIFY_RESTORE=1` in `.env` under `herdr plugin config-dir zenderx.herdr-navigator` adds a notification (off by default). PowerShell panes are restored in their live folder by herdr itself, so they are normally `same`. Remove it once herdr persists the live folder.
- The plugin now sends keystrokes to panes: only the `cd` above, only into idle shells it just restored.
- Spawn-folder check: `cwd-return` now returns a pane only when the spawn folder recorded before the restart and the restored pane's spawn folder are both known and equal. The spawn folder comes from the first spawn-form reading or else from `herdr pane process-info` (the idle shell's process cwd, the folder herdr restores the pane into), on Linux and macOS too; `cwd-record` reads it, with the shell pid, for each pane whose line lacks it or whose live folder changed, so older records are filled at the next hook. New skip reason `unknown-spawn`, before `mismatch`, when either side is unknown: such a pane stays in herdr's folder instead of being `cd`'d unchecked. After a restart, `cwd-record` leaves existing lines alone until `cwd-return` has decided (new server-run stamp `cwd-<session>.instance`). A failed `process-info` during the busy check now counts as `busy`.
- Nothing needs to be added to `~/.bashrc`, `$PROFILE` or any other shell startup file, and nothing in the plugin depends on a shell snippet. If you added an earlier snippet you may remove it, nothing uses it.
- Linux: the sh scripts passed every row live against herdr 0.9.5 in a Debian container (`bash scripts/cwd-restore-probe/linux/run.sh`). herdr restores the live folder on Linux, so panes there are normally `same`. macOS remains untested.
- New discovery popup that offers the Herdr Navigator VS Code extension when herdr was started from a VS Code terminal, or a new space's folder looks like a VS Code project, and the extension is not installed. It runs on `startup` and `workspace.created`; `tab.created` was measured but left out because it also fires for each new space's first tab. At most three appearances, 30 days apart; "Never" and an installed extension stop it. An appearance counts once the popup opens, answered or not. Before opening, a hook checks that a client is attached with `herdr notification show`, which shows a short "Herdr Navigator" toast, and opens nothing otherwise; if the open then fails, further triggers that day skip the check, so a failing open costs at most one toast a day. Arrow and function keys are ignored; a bare Esc is Not now. Nothing installs without a click in VS Code.
- The manifest description and the first line of this README now mention the pairing with Herdr Navigator for VS Code.
- New "Open in VS Code" action (`open-in-vscode`, and `open-in-vscode-windows` on Windows). It opens a link the Herdr Navigator extension handles and shows a notification about detaching with `prefix+q`.
- Renamed the plugin id from `zenderx.refocus-last-space` to `zenderx.herdr-navigator` and its display name to "Herdr Navigator". Unlink the old id and link or install the plugin again.
